# 추가 기능 검수 및 반영 기록

검수일: 2026-09-21

대상: 기준 커밋 `50ae0c8`의 PDF → TXT, 다중 파일 우클릭 처리 및 기존 변환·다국어 UI와의 연동.

## 최종 판정

초기 검수에서 문제를 재현한 뒤, 사용자 확정 방침에 따라 해당 기능을 제거하고 정상 기능을 다시 검증했다. **수정된 소스로 포터블 EXE를 빌드했다.**

초기 실패와 재현 절차는 아래에 기록하고, 현재 결과는 `반영 완료` 섹션에 정리한다.

## 반영 완료

- PDF → TXT 입력 형식·엔진 분기·우클릭 메뉴·테스트·지원 문서에서 제거.
- 탐색기 다중 선택 전달을 제거하고 단일 파일 명령을 `"%1"`로 복원. `MultiSelectModel`과 `%*`를 사용하지 않음.
- 보존 한계가 있는 변환은 `XXX로 불완전 변환` 형식으로 표시하며 16개 UI 언어에 번역 추가. 형식 내부 값과 표시 문구는 분리.
- 메인 창 하단에 작은 `v1.0.0` 표시 추가.
- 기존 이미지·영상·음성·PDF 페이지·PPT 변환 기능은 유지.
- 자동 테스트 22개 통과, 소스 진단 12개 통과, 포터블 EXE 자체 검사 통과.
- 최신 EXE: `dist/Simple File Converter.exe` 및 상위 `outputs/Simple File Converter.exe`.

## 사용자 확정 수정 방침

아래 내용은 다음 구현에 적용할 요구사항이다. 이 문서 수정만으로 프로그램이나 EXE에 반영된 것은 아니다. 아래 검수 기록은 유지하되, 실패 기능을 보완하여 유지한다는 이전 계획은 기능 제거 방침으로 대체한다.

### 불완전 변환 문구

- 기존 변환 중 서식·내용·화질·애니메이션·편집 구조 등이 완전히 유지되지 않거나 문제가 생길 수 있는 항목은 **`XXX로 불완전 변환`**으로 표시한다. 예: `PPTX로 불완전 변환`.
- 기존의 `(손상 가능)`, `(손상될 수 있음)` 표시 계획을 이 문구로 대체한다. 이미지 슬라이드, 첫 프레임만 저장 등 구체적인 제한 설명은 상세 안내에 유지한다.
- 메인 창의 출력 형식 선택과 우클릭 변환 메뉴에 같은 기준을 적용한다. 내부 형식 값(`pptx` 등)은 표시 문구와 분리하여 그대로 사용한다.
- 지원 중인 16개 UI 언어 모두 해당 언어로 같은 의미를 전달한다. 한국어 문구를 그대로 노출하거나 일부 언어에서 경고를 누락하지 않는다.
- 불완전 변환은 결과의 보존 한계를 뜻한다. 실제 실행 실패를 불완전 변환 성공으로 표시하지 않으며, 원본 파일은 보존한다.

### 하단 버전 표시

- 프로그램 메인 창 하단에 현재 버전을 작게 표시한다. 초기 표시값은 **`v1.0.0`**이다.
- 모든 UI 언어에서 `v주버전.부버전.패치버전` 형식을 동일하게 유지한다.
- 버전 값은 한 곳에서 관리하고, 이후 릴리스 시 실제 배포 버전과 함께 갱신한다.
- 하단의 언어 선택 및 우클릭 활성화 체크박스를 가리지 않도록 배치한다.

### 실패 기능 제거

- 이번 검수에서 문제가 확인된 **PDF → TXT**와 미완성인 **탐색기 다중 선택 변환**은 이번 배포에서 제거한다. 해당 기능을 고쳐서 유지하는 기존 작업 순서는 적용하지 않는다.
- PDF → TXT는 메인 창 선택 목록, 우클릭 메뉴, 변환 실행 경로 및 지원 문서에서 제거한다.
- 탐색기 다중 선택 추가분은 제거하고 기존 단일 파일 우클릭 변환으로 복원한다. 단일 파일 전달 명령과 메뉴 등록을 검증한다.
- 기존 메인 창의 여러 파일 처리, 기존 PDF → 이미지/PPTX 등 정상 기능은 유지한다. 다중 우클릭 제거를 기존 일괄 변환 전체 제거로 확대하지 않는다.
- 제거 기능 전용 코드·테스트·지원 표기를 정리하고, 제거된 형식이나 실행 경로가 계속 호출되지 않는지 확인한다. 기존 등록 정보도 다음 메뉴 재등록 시 반영한다.
- 테스트 코드의 잘못된 조건이나 검증 환경의 권한 제한만으로 정상 기존 기능을 제거하지 않는다. 실제 Office 연동 미검증과 기능 자체의 실패를 구분한다.

## 수정이 필요한 항목

### 1. 탐색기에서 선택 파일을 받는 경로

`src/shell_menu.py`는 명령 끝에 `%*`만 붙이고, 주석에서는 이것이 선택 파일 전체라고 가정한다. 그러나 파일명 자리표시자인 `"%1"`이 없고, `MultiSelectModel=Player` 등록만으로 선택 목록을 한 프로세스에 전달하는 구현이 완성되는 것은 아니다.

Microsoft의 [메뉴 명령 설명](https://learn.microsoft.com/en-us/windows/win32/shell/context)은 파일명 인자에 `"%1"`을 사용한다. [선택 모델 설명](https://learn.microsoft.com/en-us/windows/win32/shell/how-to-employ-the-verb-selection-model)은 다중 선택 모델과 제한을 설명한다. 현재 `%*` 구현의 실제 동작은 권한 제한 때문에 이 환경에서 재현 검증하지 못했으므로, 단일 파일 회귀 위험 및 다중 선택 미검증으로 판정한다.

반영 방침: 미완성 다중 선택 추가분을 제거하고 단일 파일 우클릭으로 복원한다. 공백·한글 파일명, 원본 폴더 저장, 기존 결과 파일 보호를 검증한다. 여러 경로를 직접 넘기는 테스트를 탐색기 다중 선택 검증으로 간주하지 않는다.

### 2. 텍스트 없는 PDF의 잘못된 성공 표시

`src/engine.py`의 TXT 분기는 모든 페이지의 추출 결과가 비어도 줄바꿈을 쓴다. 마지막 검사는 파일 크기만 확인하므로 내용 없는 TXT를 성공으로 반환한다.

재현: PyMuPDF로 빈 1페이지 PDF를 만들고 `convert(pdf, 'txt', folder)` 호출. 결과 파일 내용은 `b'\n'`이며 예외 없이 경로를 반환했다. 이미지로만 이루어진 스캔 PDF에도 같은 문제가 적용된다.

반영 방침: 이번 배포에서 PDF → TXT 기능을 제거한다. UI·우클릭·엔진·지원 문서에서 제거 여부를 확인하고 기존 PDF 변환은 유지한다. 재도입은 별도 요청과 검증 이후 검토한다.

### 3. 다중 변환 결과 안내의 부족한 정보

`src/quick_convert.py`는 파일별 상태를 누적하지만 실패 상세에 원본 파일명이 없고, 성공과 취소가 섞이면 완료 개수·이미 저장된 결과를 요약하지 않는다. 오류 창도 2.5초 후 닫히며, 종료 후 상세를 다시 확인하는 경로가 없다. 개발 계획의 배치 진행·결과 보존 기준을 아직 충족하지 못한다.

반영 방침: 다중 우클릭 전용 결과 처리도 함께 제거한다. 기존 단일 파일 성공·실패·취소 안내와 2.5초 알림 규칙은 유지한다.

### 4. 실패한 테스트 자체의 잘못된 조건

`tests/test_shell_menu.py`의 `test_format_commands_accept_multiple_selected_files`는 전체 레지스트리 경로에 `jpg`가 있으면 JPG 출력 명령이라고 가정한다. JPG **입력** 그룹의 PNG 등 다른 출력도 포함하므로 실패한다.

반영 방침: 제거할 다중 선택 기능 전용 테스트를 정리하고 단일 파일 명령의 출력 verb와 인자 전달을 확인한다. 잘못된 테스트 조건 때문에 기존 JPG 변환 자체를 제거하지 않는다.

## 재검수와 포터블화 조건

1. PDF → TXT와 미완성 다중 우클릭 기능 제거, 기존 단일 파일 우클릭 복원.
2. 유지하는 변환의 품질 제한을 분류하고 `XXX로 불완전 변환` 문구를 16개 언어에 적용.
3. 메인 창 하단에 작은 `v1.0.0` 표시 추가.
4. 지원 문서와 테스트를 실제 기능에 맞게 정리하고 기존 변환·언어 전환·하단 배치 회귀 검사.
5. 실제 사용자 Windows 세션의 단일 파일 우클릭·Office 검사. 미검증 항목을 통과로 간주하지 않기.
6. 검수 통과 후에만 EXE 빌드, 패키지 자체 검사와 시작 검사, 체크섬 생성.

Word/HWP/PDF↔HTML·Markdown 등은 개발 계획의 후속 기능이다. 이번 코드에 구현되어 있거나 검수 완료된 것으로 간주하지 않는다.
